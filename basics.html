01. The Memory Bank

In programming, a Variable is a named space in your computer's memory. Imagine a warehouse full of boxes; a variable is the label on the box that tells you what's inside.

  • const: Use this for values that are "Locked." If you try to change it later, the system will error out. (e.g., your Date of Birth).
  • let: Use this for values that "Flow." These can be updated as the program runs. (e.g., a game score).
const userName = "Neon_Coder";
let userLives = 3;

02. Data Blueprints

JavaScript needs to know what kind of data it is handling to process it correctly. We call these Data Types.

  1. Strings: Textual data wrapped in quotes: "Direct Entry".
  2. Numbers: Plain digits (no quotes): 42 or 19.99.
  3. Booleans: Simple logic gates. Only two states exist: true or false.

Pro Tip: Putting numbers in quotes makes them Strings! "10" is text; 10 is math-ready.

03. The Logic of Math

Your CPU is a world-class calculator. JavaScript uses standard Operators to manipulate numerical data.

  • + (Addition) | - (Subtraction)
  • * (Multiplication) | / (Division)
  • % (Modulo): This gives you the Remainder of a division. Very useful for finding even or odd numbers!
let calculation = (10 * 5) + 2; // Result: 52

06. Comparison Operators

In JavaScript, we don't just store data; we compare it. To check if two values are exactly the same, we use the Strict Equality operator: ===.

  • === : Checks if value AND type are equal.
  • !== : Checks if two values are NOT equal.
  • > / << /code> : Greater than or Less than.
"10" === 10; // false (String vs Number)
10 === 10; // true

07. The If Statement

The if statement is the "Brain" of your script. It tells the computer: "If this condition is true, run this specific block of code."

if (userLives > 0) {
  // This code runs only if lives > 0
  console.log("System Active");
}

If the condition is false, the computer simply skips that block entirely.

08. Code Comments

Writing code is only half the job; the other half is making sure humans can read it. We use Comments to leave notes that the computer ignores.

  • // : Single-line comment.
  • /* ... */ : Multi-line block comment.

Pro Tip: Use comments to explain WHY you wrote the code, not just WHAT the code does.
